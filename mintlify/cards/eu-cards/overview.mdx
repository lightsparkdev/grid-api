The rest of the cards docs describe the US program, where Grid approves
every purchase. EU cards use the same `/cards` API, but the card issuer
approves their purchases instead, so several features work differently or
not at all. This section covers only what's different.

- **US cards** spend USD. Grid decides every authorization, so all of
  Grid's spending controls apply, including your own real-time decisions.
- **EU cards** have `currency: EUR` and spend from one of the
  cardholder's own accounts: EUR, USDC, or BTC. The card issuer decides
  every authorization, and it checks only the account balance, the card's
  status, and the card's own limits. Grid records each transaction and
  sends you the same webhooks, but it does not take part in the decision.

To set up an EU card, see [Issuing EU cards](/cards/eu-cards/issuing) and
[Funding EU cards](/cards/eu-cards/funding).

## Check a card at runtime

Don't branch on region. Read `cardCapabilities` on the card or on the
funding account instead. It tells you what that card's program supports,
and it stays correct as support changes.

| Capability | US | EU |
|------------|----|----|
| `supports3dSecurePassword` | `false` | `true` |
| `supportsPanReveal` | `true` | `false` |
| `supportsDigitalWalletTokenization` | `true` | `false` |

## Feature comparison

| Feature | US cards | EU cards |
|---------|----------|----------|
| Card form | Virtual | Virtual |
| Cardholder | Individual and business customers | Individual customers only |
| Funding source | A USD account or a USDB embedded wallet | One of the cardholder's own accounts: their default EUR account, or their USDC or BTC account. See [Funding EU cards](/cards/eu-cards/funding) |
| 3-D Secure password (`threeDSecurePassword`) | Not accepted | Required at issuance; change it with `PATCH /cards/{id}` |
| Who approves purchases | Grid | The card issuer, on balance and card limits only |
| [Real-time authorization](/cards/transactions/real-time-authorization) | Supported | Not supported |
| [Velocity limits](/cards/card-management/velocity-limits) | Per card or platform-wide; amount or count | Per card only, with tighter rules. See [Velocity limits on EU cards](#velocity-limits-on-eu-cards) |
| Merchant category lists (`allowedMccs`, `blockedMccs`) | Supported | Rejected with `INVALID_INPUT` |
| Network risk ceiling (`maxNetworkRiskScore`) | Supported | Rejected with `INVALID_INPUT` |
| Freeze, unfreeze, and close | Supported | Supported |
| Show the card number and CVV (`POST /cards/{id}/reveal`) | Supported | Not supported. Returns `409 CONFLICT` |
| [PINs](/cards/card-management/pins) | Supported | Not supported. Returns `409 CONFLICT` |
| [In-app wallet provisioning](/cards/card-management/digital-wallet-tokenization) | Apple Pay, Google Pay, Samsung Pay | Not supported. Returns `409 CONFLICT` |
| Agent cards (`agentId`) | Supported | Rejected with `INVALID_INPUT` |
| Transaction webhooks | Supported | Supported |
| Disputes | Through Grid | Contact Lightspark support |
| [Sandbox simulation](/cards/platform-tools/sandbox-testing) | Supported | Not supported. Returns `409 CONFLICT` |

## Velocity limits on EU cards

The card issuer enforces EU card limits itself, so it accepts a narrower
set of rules:

- Create each rule with a `cardId`. Platform-wide rules don't apply to EU
  cards.
- Use `metric: APPROVED` with `maxAmount`. Count limits (`maxCount`) are
  rejected.
- Use an `AUTHORIZATION`, `DAY`, or `MONTH` window.
- Set `maxAmount` in cents, as a whole number of euros. `5000` (€50.00)
  is accepted; `5050` is not.
- Stay within the card's ceilings: €10,000 for a single authorization or a
  day, and €15,000 for a month. A new card starts at these ceilings.
- Change limits only while the card is `ACTIVE`. Otherwise you get
  `409 CONFLICT`.

See [Velocity limits](/cards/card-management/velocity-limits) for the
request shape.

## When a feature isn't available

An unsupported action returns an error instead of being ignored:

- Fields that EU cards can't honor on `POST /cards` or `PATCH /cards/{id}`,
  such as `allowedMccs` or `maxNetworkRiskScore`, return `400 INVALID_INPUT`.
- Actions that EU cards don't support, such as reveal, PIN management,
  wallet provisioning, and simulation, return `409 CONFLICT`. Retrying won't
  help. Check `cardCapabilities` first and hide the action in your app.
