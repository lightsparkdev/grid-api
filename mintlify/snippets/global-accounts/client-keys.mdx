Every signed Global Account action uses two key pairs:

| Key pair | Where it lives | What it does |
|---|---|---|
| **Client key pair** (P-256) | On the customer's device, generated fresh per session-issuing or export request | For authentication and session refresh, its private key becomes the session signing key. For wallet export, its public key is the recipient key Grid encrypts the wallet credentials to. Ephemeral — one pair per authentication, session refresh, or wallet export. |
| **Session signing key** (P-256) | Held on the customer's device | Signs every account action for the lifetime of the session (default 15 minutes). It is the private key of the client key pair sent on the request that issued the session. |

This page covers generating the client key pair, sending the public key to your backend, holding the session signing key, and signing payloads. Everything here runs **on the client**; your integrator backend only relays opaque byte strings.

## 1. Generate a client key pair

The key pair you generate here *is* your session key: you keep the private key on the device and use it directly to sign account actions. Grid never transmits a session key, so session-issuing responses carry no key material. Generate it as a P-256 **signing** key (ECDSA).

Generate a fresh key pair for every authentication and session refresh. Where the public key goes depends on the flow:

- `PASSKEY`: send it as `clientPublicKey` on `POST /auth/credentials/{id}/challenge`.
- `OAUTH`: send it as `clientPublicKey` on `POST /auth/credentials/{id}/verify`.
- `EMAIL_OTP`: put it inside `encryptedOtpBundle` on `POST /auth/credentials/{id}/verify`. See <a href="#encrypt-the-otp-code-email_otp-only">Encrypt the OTP code</a>.
- Session refresh: send it as `clientPublicKey` on both `/auth/sessions/{id}/refresh` calls.

Wallet export uses a different kind of key pair. See <a href="#wallet-export-key-pair">Wallet export key pair</a>.

Keep the private key in device-local secure storage (iOS Keychain, Android Keystore, or in the browser, `IndexedDB` encrypted under a non-extractable Web Crypto key). Send the public key through your integrator backend as a **compressed** SEC1 point in **lowercase** hex: 66 characters, a `02` or `03` prefix followed by the 32-byte X coordinate. Grid rejects an uppercase or uncompressed key with `400 INVALID_INPUT`.

<Tip>
  For local development, you can generate a P-256 key pair from the command line:
  ```bash
  # Private key (PKCS#8 PEM)
  openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out private.pem

  # Compressed public key as lowercase hex
  openssl ec -in private.pem -pubout -conv_form compressed -outform DER 2>/dev/null \
    | tail -c 33 | xxd -p -c 33
  ```
</Tip>

```typescript Web (TypeScript)
// npm i @noble/curves
import { p256 } from "@noble/curves/nist.js";

function bytesToHex(bytes: Uint8Array): string {
  return Array.from(bytes, (byte) => byte.toString(16).padStart(2, "0")).join("");
}

// Generate a P-256 signing key pair. The 32-byte private key becomes the
// session signing key, so store it encrypted at rest on the device.
function generateClientKeyPair(): {
  privateKey: Uint8Array;
  publicKeyHex: string;
} {
  const privateKey = p256.utils.randomSecretKey();
  // Compressed SEC1 form: 33 bytes, 0x02 or 0x03 followed by X.
  const publicKeyHex = bytesToHex(p256.getPublicKey(privateKey, true));

  return { privateKey, publicKeyHex };
}
```

```kotlin Android (Kotlin)
import android.security.keystore.KeyGenParameterSpec
import android.security.keystore.KeyProperties
import java.math.BigInteger
import java.security.KeyPairGenerator
import java.security.interfaces.ECPublicKey
import java.security.spec.ECGenParameterSpec

data class ClientKeyPair(val alias: String, val publicKeyHex: String)

private fun BigInteger.toFixed32(): ByteArray {
    val bytes = toByteArray()
    return ByteArray(32).also { out ->
        val copyFrom = maxOf(0, bytes.size - 32)
        val copyLength = bytes.size - copyFrom
        System.arraycopy(bytes, copyFrom, out, 32 - copyLength, copyLength)
    }
}

fun generateClientKeyPair(alias: String): ClientKeyPair {
    val generator = KeyPairGenerator.getInstance(
        KeyProperties.KEY_ALGORITHM_EC,
        "AndroidKeyStore",
    )
    generator.initialize(
        KeyGenParameterSpec.Builder(alias, KeyProperties.PURPOSE_SIGN)
            .setAlgorithmParameterSpec(ECGenParameterSpec("secp256r1"))
            .setDigests(KeyProperties.DIGEST_SHA256)
            .build(),
    )
    val point = (generator.generateKeyPair().public as ECPublicKey).w
    // Compressed SEC1 form: 0x02 for an even Y, 0x03 for an odd Y, then X.
    val prefix = if (point.affineY.testBit(0)) 0x03.toByte() else 0x02.toByte()
    val compressed = byteArrayOf(prefix) + point.affineX.toFixed32()
    val hex = compressed.joinToString("") { "%02x".format(it) }
    return ClientKeyPair(alias = alias, publicKeyHex = hex)
}
```

### Wallet export key pair

Wallet export encrypts the wallet credentials to the key you send, so it needs a P-256 **key agreement** (ECDH) key pair rather than a signing key. Generate a fresh one for each export and discard the private key after decrypting. Send its public key as `clientPublicKey` on both `/export` calls, as an **uncompressed** SEC1 point in **lowercase** hex: 130 characters, a `04` prefix followed by the 32-byte X and 32-byte Y coordinates. The samples below produce that form. See <a href="exporting-wallet">Exporting a wallet</a> for the full flow.

<CodeGroup>
```typescript Web (TypeScript)
function bytesToHex(bytes: Uint8Array): string {
  return Array.from(bytes, (byte) => byte.toString(16).padStart(2, "0")).join("");
}

// Generate a non-extractable P-256 key pair in the browser.
// The private key never leaves Web Crypto; only the public key is exported.
async function generateExportKeyPair(): Promise<{
  keyPair: CryptoKeyPair;
  publicKeyHex: string;
}> {
  const keyPair = await crypto.subtle.generateKey(
    { name: "ECDH", namedCurve: "P-256" },
    false, // private key non-extractable
    ["deriveBits"],
  );

  const raw = new Uint8Array(
    await crypto.subtle.exportKey("raw", keyPair.publicKey),
  );
  // exportKey("raw") returns the 65-byte uncompressed form (0x04 || X || Y).
  const publicKeyHex = bytesToHex(raw);

  return { keyPair, publicKeyHex };
}
```

## Encrypt the OTP code (`EMAIL_OTP` only)

`EMAIL_OTP` credentials never send the OTP code in plaintext. Instead, the client HPKE-encrypts the code, together with its public key, to an enclave key, so the code is unreadable in transit and Grid is only a pass-through.

Grid returns an `otpEncryptionTargetBundle` whenever it initiates or reissues an OTP challenge, including `POST /auth/credentials/{id}/challenge` and add-EMAIL_OTP signed-retry responses. First-time EMAIL_OTP wallet bootstrap registration can omit it; if the registration response has no bundle, call `POST /auth/credentials/{id}/challenge` for that credential before verifying. The bundle is a signed enclave bundle whose `data` field is hex-encoded JSON carrying the enclave's HPKE target key as `targetPublic`. Pull out `targetPublic`, HPKE-encrypt `{ otp_code, public_key }` to it, and submit the library's `{ encappedPublic, ciphertext }` output as `encryptedOtpBundle` on `POST /auth/credentials/{id}/verify`.

`public_key` must be the **compressed** public key in lowercase hex: 66 characters starting with `02` or `03`. The step 1 samples produce this form. The OTP login challenge is bound to this exact key, so the same compressed hex must be the `publicKey` in the `Grid-Wallet-Signature` stamp on the signed retry (see <a href="#2-sign-a-payloadtosign">step 2</a>); a different value there fails the login.

In production, an uncompressed key makes the enclave reject the OTP code, even when the code is correct. The first verify call then returns:

```json
{"code": "INVALID_INPUT", "reason": "Invalid wallet request."}
```

Grid returns this same response for other rejected requests too, including a mistyped OTP code. If you get it with a code you know is correct, check the key format first.

Use an HPKE library so you don't hand-roll the suite, `info`, or AAD. The
helper below assumes your crypto layer returns the JSON string Grid expects for
`encryptedOtpBundle`.

```typescript Web (TypeScript)
// npm i @noble/hashes
import { hexToBytes } from "@noble/hashes/utils.js";

declare function hpkeEncryptToGridBundle(args: {
  plainTextBuf: Uint8Array;
  targetKeyBuf: Uint8Array;
}): string;

// otpEncryptionTargetBundle: from the registration response when present, or /challenge
// clientPublicKeyHex: the compressed public key from step 1
// otp: the code the user typed ("000000" in sandbox)
function buildEncryptedOtpBundle(
  otpEncryptionTargetBundle: string,
  clientPublicKeyHex: string,
  otp: string,
): string {
  // Pull the enclave's target key out of the signed bundle.
  const { data } = JSON.parse(otpEncryptionTargetBundle) as { data: string };
  const { targetPublic } = JSON.parse(
    new TextDecoder().decode(hexToBytes(data)),
  ) as { targetPublic: string };

  // The enclave expects snake_case keys.
  const plainTextBuf = new TextEncoder().encode(
    JSON.stringify({ otp_code: otp, public_key: clientPublicKeyHex }),
  );
  return hpkeEncryptToGridBundle({
    plainTextBuf,
    targetKeyBuf: hexToBytes(targetPublic),
  });
}
```

<Note>
  A production client should also verify the bundle's `dataSignature` against its `enclaveQuorumPublic` before trusting `targetPublic`.
</Note>

The private key of the pair you generated in step 1 stays on the device. It becomes the session signing key once verification completes (see <a href="#2-sign-a-payloadtosign">Sign a `payloadToSign`</a>).

## 2. Sign a `payloadToSign`

Grid returns `payloadToSign` strings from several endpoints:

- `POST /quotes` (when the source is a Global Account) — the quote's `paymentInstructions[].accountOrWalletInfo.payloadToSign`.
- `POST /auth/credentials/{id}/verify` (`EMAIL_OTP` or `SMS_OTP`) — 202 response body; use the TEK private key generated for this login.
- `POST /auth/credentials` (adding an additional credential) — 202 response body.
- `DELETE /auth/credentials/{id}`, `DELETE /auth/sessions/{id}`, `POST /auth/sessions/{id}/refresh`, `POST /internal-accounts/{id}/export`, `PATCH /internal-accounts/{id}`, `PATCH /customers/{id}` for tied `EMAIL_OTP` email updates — all 202 response bodies.

Stamp the exact UTF-8 bytes of the `payloadToSign` string **as returned** (do not re-parse, re-serialize, or trim whitespace). For OTP verification, use the matching TEK private key; for other signed wallet actions, use an active session signing key. Build a Grid wallet signature: take its compressed P-256 public key in lowercase hex, sign the payload with the private scalar, then base64url-encode the signature envelope:

```json
{
  "publicKey": "<compressed P-256 public key hex>",
  "scheme": "SIGNATURE_SCHEME_TK_API_P256",
  "signature": "<DER ECDSA signature hex>"
}
```

Pass that full stamp as the `Grid-Wallet-Signature` header on the retry (and, for endpoints that use it, echo the 202 `requestId` as `Request-Id`).

<Note>
  Use real stamps in sandbox to exercise the same signing flow as production. OTP verification requires a stamp over the returned `payloadToSign` with the TEK private key. Some other signed wallet actions still accept the legacy `sandbox-valid-signature` shortcut, but it does not validate your client's signing implementation.
</Note>

<CodeGroup>
```typescript Web (TypeScript)
declare function deriveCompressedP256PublicKey(privateKeyHex: string): string;
declare function signP256Sha256Der(args: {
  content: string;
  privateKeyHex: string;
}): Promise<string>;

const GRID_STAMP_SCHEME = "SIGNATURE_SCHEME_TK_API_P256";

function bytesToHex(bytes: Uint8Array): string {
  return Array.from(bytes, (byte) => byte.toString(16).padStart(2, "0")).join("");
}

function base64url(bytes: Uint8Array): string {
  let binary = "";
  for (const byte of bytes) {
    binary += String.fromCharCode(byte);
  }
  return btoa(binary).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
}

async function buildGridWalletSignature(
  sessionPrivateKeyBytes: Uint8Array, // 32 bytes, the step 1 private key
  payloadToSign: string,
): Promise<string> {
  const apiPrivateKey = bytesToHex(sessionPrivateKeyBytes);
  const apiPublicKey = deriveCompressedP256PublicKey(apiPrivateKey);
  const signature = await signP256Sha256Der({
    content: payloadToSign,
    privateKeyHex: apiPrivateKey,
  });
  const stamp = JSON.stringify({
    publicKey: apiPublicKey,
    scheme: GRID_STAMP_SCHEME,
    signature,
  });
  return base64url(new TextEncoder().encode(stamp));
}
```

```kotlin Android (Kotlin)
import android.util.Base64
import java.security.KeyStore
import java.security.PrivateKey
import java.security.Signature

private const val GRID_STAMP_SCHEME = "SIGNATURE_SCHEME_TK_API_P256"

private fun ByteArray.hex(): String = joinToString("") { "%02x".format(it) }

private fun base64url(value: String): String =
    Base64.encodeToString(
        value.toByteArray(Charsets.UTF_8),
        Base64.URL_SAFE or Base64.NO_PADDING or Base64.NO_WRAP,
    )

fun buildGridWalletSignature(
    sessionKeys: ClientKeyPair, // from generateClientKeyPair in step 1
    payloadToSign: String,
): String {
    val keyStore = KeyStore.getInstance("AndroidKeyStore").apply { load(null) }
    val privateKey = keyStore.getKey(sessionKeys.alias, null) as PrivateKey
    val signer = Signature.getInstance("SHA256withECDSA").apply {
        initSign(privateKey)
        update(payloadToSign.toByteArray(Charsets.UTF_8))
    }
    val derSignatureHex = signer.sign().hex() // JCE returns DER-encoded ECDSA.
    val stampJson = """{"publicKey":"${sessionKeys.publicKeyHex}","scheme":"$GRID_STAMP_SCHEME","signature":"$derSignatureHex"}"""
    return base64url(stampJson)
}
```

```swift iOS (Swift)
import CryptoKit
import Foundation

func buildGridWalletSignature(
    signingKey: P256.Signing.PrivateKey, // from generateClientKeyPair in step 1
    payloadToSign: String,
) throws -> String {
    let payload = Data(payloadToSign.utf8)
    let signature = try signingKey.signature(for: payload)
    let signatureHex = signature.derRepresentation.map { String(format: "%02x", $0) }.joined()
    let publicKeyHex = signingKey.publicKey.compressedRepresentation
        .map { String(format: "%02x", $0) }
        .joined()
    let stampJson = #"{"publicKey":"\#(publicKeyHex)","scheme":"SIGNATURE_SCHEME_TK_API_P256","signature":"\#(signatureHex)"}"#
    return Data(stampJson.utf8)
        .base64EncodedString()
        .replacingOccurrences(of: "+", with: "-")
        .replacingOccurrences(of: "/", with: "_")
        .replacingOccurrences(of: "=", with: "")
}
```

## Session lifetime

Sessions are valid for 15 minutes by default. The `AuthSession.expiresAt` field tells you exactly when the session signing key stops being accepted. After expiry, the client must re-verify the credential (see <a href="authentication">Authentication</a>) to obtain a fresh session.

<Warning>
  If the device is lost or compromised, the user should add a second credential from a trusted device and revoke the compromised one — see <a href="authentication#managing-credentials">Managing credentials</a>. To end the current browser or app session without touching credentials, see <a href="managing-sessions">Sessions</a>.
</Warning>
