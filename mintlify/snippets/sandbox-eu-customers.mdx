A sandbox platform created with `EUR` among its currencies simulates the extra steps Grid requires for EU customers in production: contact verification, Strong Customer Authentication (SCA), wallet ownership proof, and Travel Rule holds on USDC deposits. Sandbox sends no email or SMS. Every one-time code is `000000`.

### Contact verification

Confirm the customer's email and phone with the code `000000` on `verify-email/confirm` and `verify-phone/confirm`. Until both are `VERIFIED`, `POST /customers/{customerId}/kyc-link` returns `409`.

### SCA codes

| Code | Endpoint | Result |
|------|----------|--------|
| `000000` | Any SCA proof: login, factor enrollment, quote authorization, and beneficiary trust | Accepted |
| `111111` | `POST /quotes/{quoteId}/authorize` | Returns `400`. The challenge expires and the payout fails with `failureReason: SCA_NOT_COMPLETED` |
| Any other code | Any SCA proof | Returns `400`. The challenge stays open |

Sandbox verifies passkey assertions as production does. Resending a challenge's code more than five times returns `429`.

The external account suffixes that pick a payout's outcome apply once the quote is authorized.

### Wallet ownership

A self-hosted wallet is `PENDING_OWNERSHIP_VERIFICATION` until the customer proves they own it. Sandbox verifies a `WALLET_SIGNATURE` proof as production does.

A `LIVENESS` check resolves about 60 seconds after it starts. The last three characters of the wallet address pick the result. A Solana address can't contain `0`, so it uses `1` in place of the leading `0`.

| Address ends in | Result |
|-----------------|--------|
| `051` (Solana: `151`) | The check fails and the wallet moves to `UNVERIFIED` |
| `052` (Solana: `152`) | The check stays in review and the wallet stays `PENDING_OWNERSHIP_VERIFICATION` |
| Anything else | The check passes and the wallet moves to `ACTIVE` |

### USDC deposits and the Travel Rule

To simulate a USDC deposit from a specific wallet, pass its address as `senderAddress` when you fund the customer's USDC account. The address must be on Ethereum or Solana.

```bash
curl -X POST https://api.lightspark.com/grid/2025-10-13/sandbox/internal-accounts/{accountId}/fund \
  -u "$GRID_CLIENT_ID:$GRID_CLIENT_SECRET" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 10000000, "senderAddress": "0x1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b" }'
```

The customer's saved wallet for that address decides what happens to the deposit. The sandbox Travel Rule threshold is 5 USDC.

| Sending wallet | Amount | Result |
|----------------|--------|--------|
| Not saved by the customer | Any | `PENDING` with `pendingReason: COUNTERPARTY_DECLARATION_REQUIRED` |
| An exchange wallet (`vaspName` set) | Any | `PENDING` with `pendingReason: COMPLIANCE_REVIEW`, then credited about 60 seconds later |
| A self-hosted wallet | Under 5 USDC | Credited |
| Someone else's self-hosted wallet (`ownershipType: THIRD_PARTY`) | 5 USDC or more | `FAILED` with `failureReason: COMPLIANCE_REJECTED` |
| The customer's own wallet, not yet verified | 5 USDC or more | `PENDING` with `pendingReason: WALLET_VERIFICATION_REQUIRED` |
| The customer's own wallet, verified | 5 USDC or more | Credited |

When the customer saves or verifies the sending wallet, Grid decides a held deposit again. A deposit the wallet now clears moves to `COMPLIANCE_REVIEW` and is credited about 60 seconds later. Saving the wallet as `THIRD_PARTY` fails a deposit of 5 USDC or more.

On a sandbox platform without `EUR`, Grid ignores `senderAddress` and credits the deposit.

### Requests refused as in production

Sandbox refuses the same requests for EU customers as production:

- `POST /quotes/{quoteId}/execute` without a live SCA login session returns `409 SCA_SESSION_REQUIRED`.
- A quote with a `REALTIME_FUNDING` source returns `400`.
- `POST /transfer-out` returns `400`.
- Executing a payout with `scaFactor: TOTP` returns `400`.
- Saving a wallet without `ownershipType` returns `400`.
- A payout to a Polygon wallet returns `400`.
- Starting beneficiary trust for a business customer returns `501`.

### Not simulated

- A payout that converts USDC before sending asks for one authorization. Production asks for one per step, so keep the authorization loop described in [Per-transaction authorization](/platform-overview/sca/per-transaction-authorization).
- Sandbox doesn't simulate two-factor reset or the lockout after repeated failed SCA attempts.
